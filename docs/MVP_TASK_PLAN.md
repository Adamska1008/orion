# Orion · MVP Task Plan

当前迭代：做一个能扫描真实目录、流畅浏览占用的只读桌面版本。**状态：核心流程已实现，用户试用中；已提供 Release 基线版。** 勾选表示对应实现或验证已完成，完整桌面验收与整盘性能优化仍在进行。

产品方向见 [Product Spec](PRODUCT_SPEC.md)，架构与技术选择见 [Tech Stack](TECH_STACK.md)。本文只管理这一轮做什么、按什么顺序做、怎样确认能用，不代表后续完整路线图。

## 本轮范围

**选目录 → 扫描 → 按大小浏览 → 逐层进入与返回 → 取消或重扫。**

- 独立 Server 管理扫描和结果，Tauri / React 界面通过后端 API 访问。
- 扫描中能看已有结果、进度和异常；取消后保留部分结果。
- 文件或目录详情能查看路径、大小和修改时间，支持复制路径与系统文件定位。
- 关闭 GUI 不自动取消任务，重新连接存活的 Server 后能继续查看。

本轮不做清理规则、删除、清理计划、持久化、MFT / USN、历史变化、重复检测或 MCP / Skill 交付。完整 CLI、复杂筛选、多选批处理、拖放和多套图形视图也不作为这一轮的完成条件。

### 2. 跑通 Server 与客户端连接

- [x] 实现连接状态查询，显示未连接、连接失败和任务失败；网络错误提示检查 Server 与连接信息。

**可检查的结果：** GUI 能识别独立 Server 的状态；断开再连接不会静默新建扫描任务。

### 3. 实现后台扫描与占用查询

- [x] 接受一个选定的本地目录范围，后台枚举文件并建立内存索引，累计目录大小。
- [x] 提供开始扫描、查询进度、取消、查询任务结果、目录列表及对象详情的 API。
- [x] 支持运行中、取消中、已取消、已完成、失败；单独标注部分结果与未覆盖范围。
- [x] 记录访问错误、文件消失和链接；不跟随重解析点，进入目录前复查范围，实际占用标为未知。普通路径枚举的并发替换边界见 README。
- [x] 列表按大小排序并分页；每页返回索引版本，可要求指定版本，不拼接不同版本的分页结果。

**可检查的结果：** 不依赖 GUI 即可完成扫描、查询和取消；已知目录的统计可核对，错误不会被隐藏。

### 4. 接入可浏览的桌面界面

- [x] 用系统目录选择对话框指定范围，连接真实扫描 API。
- [x] 展示任务状态、已发现数量、已统计大小、结果完整性和错误摘要，支持取消与重新扫描。
- [x] 实现按大小浏览、逐层进入与返回、对象详情、路径复制和系统文件定位。

**可检查的结果：** 能通过一个桌面窗口完成本轮流程；界面没有自己的扫描或统计实现。

- [ ] 试用大量小文件与大文件混合目录，观察扫描耗时、内存、API 响应和列表滚动；定位实际瓶颈后修正。
- [ ] 检查中文路径、高 DPI、键盘与鼠标交互，以及布局是否容易找到主要占用。

**完成判断：** 用户能在真实目录中走通本轮流程，扫描期间仍可浏览与取消，统计和异常有依据。没有新增问题时不反复扩张测试或功能范围。

## 本轮实现取舍

- 本机单用户运行一个 Server，开发时在两个终端分别运行后端与 GUI。使用普通 Cargo / npm 命令，不提供自定义启动、停止或联调脚本，不注册开机服务。
- 同时只运行一个扫描任务；冲突请求明确返回状态，不建立任务调度系统。
- 仅保留最近一次扫描的内存索引，新扫描替换旧结果。客户端关闭不影响存活 Server；Server 重启后原任务与结果不可恢复。
- 使用普通目录枚举与固定数量的后台工作线程，按批次发布索引，不实现暂停、续扫、事件总线或插件运行时。
- 保留系统标题栏，从目录列表和详情布局开始；组件按需引入，不为本轮预建完整设计系统。

实施或试用需要调整时，直接修改此处，避免同时维护多份范围清单。

## 环境检查记录

2026-09-20 的实现与验证记录：

- Rust / Cargo 1.92.0，Windows MSVC；Node.js 24.12.0，npm 11.12.1。依赖版本已锁定。
- 使用 `vswhere -prerelease` 找到已有 Visual Studio Insiders / MSVC 14.51；已有 Windows SDK 和 WebView2，无需另装编译器。
- Debug / Release 原生构建与前端构建通过；后端 6 项测试在两个配置下通过，前端 3 项测试通过。
- 真实 HTTP 联调验证已知目录统计、分页、认证、重复请求、冲突与扫描中取消。一次项目目录测试约 1.5 万文件、1.26 秒，期间状态查询最大约 3 ms；这不是整盘性能结论。
- 用户已试用整盘 C 盘扫描，并反馈速度偏慢。metadata 复用已默认启用，接受 NTFS 部分硬链接大小/时间可能滞后的枚举口径。现已加入目录线程池（默认最多 4 个）和每批最多 256 条目的索引更新，保留目录范围复查、链接跳过和取消后的部分结果。
- 并发改动的 Release 后端测试 13 项通过，覆盖 1/2/4/8 线程结果、扫描中取消与终态收尾、线程异常、入队目录被替换和有界错误明细。真实目录对比基线为 metadata 优化后的单线程实现；完整 C 盘体验仍需试用。
- 桌面自动交互检查由用户按 Esc 中止；GUI 重开、完整键盘操作、高 DPI 和系统集成仍待完整验收。

启动与构建步骤见 [README](../README.md)，环境要求参照 [Tauri 开发前提](https://v2.tauri.app/start/prerequisites/)。
