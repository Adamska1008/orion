## 1. 项目背景

### 1.1 背景与问题

用户经常通过 SpaceSniffer 排查磁盘空间占用，但不喜欢现有界面的呈现方式；使用 TreeSize 等工具时也遇到过卡死。现有使用体验中的主要问题是：

1. 难以快速看懂空间主要被哪些内容占用，需要反复进入目录判断。
2. 发现大文件之后，仍需要自行判断用途、保留价值和删除影响。
3. 扫描期间的卡顿或长时间无反馈，会让用户无法判断程序是否仍在工作。

Orion 希望帮助用户完成从“发现占用”到“决定如何处理”的全过程。

### 1.2 已明确的需求与偏好

| 编号 | 已明确内容 |
| --- | --- |
| N-01 | 用于排查和清理磁盘空间占用 |
| N-02 | 改善 SpaceSniffer 式界面的使用体验，具体替代交互尚未确定 |
| N-03 | 重视扫描效率，尤其需要避免扫描期间界面卡死 |
| N-04 | 先实现产品功能，再通过 MCP Server / Skill 文档让通用 Agent 使用这些能力；不在 Orion 内直接集成 AI 助手 |
| N-05 | 先明确产品需求，再开展技术选型与实现 |
| N-06 | 认可面向 Agent 的软件设计方向，将 Agent 理解为另一种客户端；关注 CLI 的使用价值、沙箱限制，以及命令与业务能力的区别 |

### 1.3 产品定位

**建议定位：提供桌面界面和可组合能力的本地磁盘空间管理工具，既支持用户直接操作，也支持通用 Agent 代用户完成任务。**

Orion 负责扫描、统计、规则分析、清理计划、执行和结果验证。GUI 与外部 Agent 是这些能力的不同使用入口；对话、模型选择和任务编排由外部 Agent 负责。

交付上仍先完成核心功能，再提供 CLI、MCP Server 和 Skill 等接入交付物；产品需求阶段就明确各项能力的输入、输出、状态与约束，使后续接入无需重做业务流程。此处的客户端分离不要求采用远程服务或特定部署架构。

核心价值：

- 看得清：快速定位主要占用和可以进一步检查的内容。
- 用得顺：扫描过程中仍可浏览结果、切换页面和取消任务。
- 决定有依据：展示清理理由、适用条件与影响，而非只给出“垃圾”标签。
- 操作可追踪：执行前有明确清单，执行后有逐项结果和恢复信息。

### 1.4 面向人和 Agent 的共同设计原则

以下为根据新讨论提炼的产品设计建议，适用于核心功能及后续接入。

| 原则 | 在 Orion 中的要求 |
| --- | --- |
| 能力独立于界面 | 核心能力可在不点击界面、不依赖当前页面选中状态的情况下调用；GUI 保留完整的人机交互流程 |
| 职责明确、可组合 | 查询占用、解释规则依据、建立清理计划、执行和验证分别有清晰结果，调用方可以组合完成任务 |
| 决策依据可见 | 返回事实、规则依据、适用条件、未知项和数据时间，支持调用方解释结果 |
| 先观察和计划，再执行与验证 | 清理以可审阅的具体计划为基础，执行后检查对象结果和磁盘空间状态 |
| 状态可查询 | 长任务、计划、执行记录有可引用的标识，换入口或中断后仍可查询已有状态 |
| 约束由产品执行 | 授权、范围、保护规则和重复执行检查在 Orion 内生效，不能只写在界面或 Skill 中 |
| 恢复能力如实表达 | 区分回收站恢复、重新生成和不可恢复，不承诺通用回滚 |
| 接口和文档可持续使用 | 能力说明、结果语义和版本可识别，变化有兼容或迁移说明 |

“能力”按完整、可验证的业务职责划分，并不要求每项能力只有一个底层动作，也不表示批量操作天然具备全部成功或全部回滚的保证。

## 2. 产品目标与成功指标

### 2.1 产品目标

| 编号 | 目标 | 成功表现 |
| --- | --- | --- |
| G-01 | 降低排查占用的成本 | 用户能从扫描结果快速找到主要占用目录和文件 |
| G-02 | 保持扫描期间可交互 | 扫描时仍能查看已有结果、浏览目录和发起取消 |
| G-03 | 支持有依据的清理决策 | 每项清理建议都能查看对象、理由、影响与处理方式 |
| G-04 | 避免未经选择的清理 | 实际执行范围与用户确认的清单一致 |
| G-05 | 让人和通用 Agent 共用产品能力 | 从核心阶段明确独立能力与状态；接入阶段，Agent 能依据 CLI / MCP 和 Skill 文档组合完成任务 |

### 2.2 建议验收指标

以下为产品目标草案，不代表已验证的性能承诺。性能验收需固定测试设备、磁盘类型、数据集和权限条件。

| 指标 | 建议目标 | 验证方式 |
| --- | --- | --- |
| 主要占用可发现性 | 扫描结果可用后，测试用户在 1 分钟内定位前三个主要占用目录 | 任务式可用性测试 |
| 扫描中的交互反馈 | 切页、展开、选择与取消点击在 1 秒内出现可见反馈 | 在约定数据集上实测 |
| 扫描状态反馈 | 扫描中至少每 2 秒更新一次状态；无新增结果时说明当前阶段 | 全程观察与记录 |
| 清理范围一致性 | 未被确认的对象不因本次操作被清理 | 对照清单与操作结果 |
| 清理结果可追踪性 | 每个执行对象都有成功、失败或跳过状态 | 检查操作记录 |
| 基础功能独立性 | 未接入外部 Agent 或断网时，扫描、浏览、规则建议和清理仍可使用 | 独立运行、断网场景验收 |
| 核心能力独立性 | 核心流程可不经 GUI 操作完成，返回可核对的结果 | 从非 GUI 调用入口验收，不要求此阶段发布 CLI 或 MCP |
| 外部工具可用性（后续阶段） | 通用 Agent 能按接入文档完成扫描、查询和清理预览 | 在选定的 Agent 客户端中按文档验收 |

全盘扫描耗时、峰值内存和大规模数据量上限，需要在需求评审时确定典型设备与数据集，再制定门槛；不预设“全盘十秒”等绝对指标。

## 3. 目标用户与使用场景

### 3.1 目标用户

首版建议优先服务个人 Windows 用户，尤其是有大量应用、开发环境、下载文件或游戏的用户。开发者相关缓存是候选重点场景，是否优先于普通用户场景待确认。

### 3.2 核心场景

| 场景 | 触发条件 | 用户希望完成的任务 | 预期结果 |
| --- | --- | --- | --- |
| S-01 磁盘即将占满 | 可用空间不足 | 找出最大占用，并决定处理哪些内容 | 得到可执行的处理清单 |
| S-02 定期整理 | 下载或工作目录杂乱 | 按大小、类型和时间筛选文件 | 找到需要人工检查的内容 |
| S-03 识别陌生目录 | 发现较大的未知目录 | 了解目录用途、所属应用和处理影响 | 得到有依据的说明或明确的未知状态 |
| S-04 扫描大量文件 | 目录包含大量小文件 | 一边扫描一边查看结果，必要时取消 | 界面持续响应，扫描状态清楚 |
| S-05 追查空间增长 | 空间近期明显减少 | 对比历史占用，定位增长来源 | 展示有历史数据支持的变化；建议后续版本提供 |
| S-06 通过通用 Agent 管理空间 | 用户希望在已有 Agent 中发起任务 | 让 Agent 调用 Orion 扫描、查询占用并生成清理预览 | 获得可核对的结果，按已授权范围继续处理；核心功能完成后提供 |
| S-07 跨入口继续任务 | 用户或 Agent 已经发起扫描或生成计划 | 在另一入口检查同一任务、计划和执行结果 | 无需重复扫描或重新拼装清单，状态和统计一致 |

## 4. 产品范围与优先级

优先级定义：**P0** 为建议首版必须具备；**P1** 为核心功能完成后优先推进的增强项；**P2** 为后续扩展。

| 功能模块 | 优先级 | 建议范围 |
| --- | --- | --- |
| 选择磁盘或目录并扫描 | P0 | 可见进度、增量结果、取消、异常提示 |
| 空间总览 | P0 | 容量信息、主要占用、分类、扫描完整性 |
| 目录与文件浏览 | P0 | 大小排序、逐层进入、筛选、详情、定位文件 |
| 规则清理建议 | P0 | 有明确识别依据的候选项，说明理由和处理影响 |
| 清理预览与执行 | P0 | 手动选择、确认清单、处理方式、逐项结果 |
| 操作记录与恢复入口 | P0 | 记录处理结果，说明是否可恢复及恢复途径 |
| 独立能力与共享任务状态 | P0 | 核心流程可脱离 GUI 调用，计划、任务及结果可引用和复核；不要求此阶段发布外部接口 |
| 通用 Agent 接入（CLI / MCP / Skill） | P1 | 核心功能完成后提供调用入口和使用文档；CLI 与 MCP 的覆盖范围、发布顺序待评审 |
| 历史快照与增长分析 | P2 | 对比不同时间的扫描结果 |
| 重复文件检测 | P2 | 确认内容重复后再形成候选项 |
| 后台增量监测 | P2 | 持续追踪空间变化，减少重复扫描 |

### 4.1 产品边界与首版排除项

已明确的产品边界：Orion 不内置 AI 聊天助手、模型运行服务、模型选择或模型供应商配置。通用 Agent 的对话与推理由用户使用的外部产品承担。

首版建议不包含：

- 未经用户授权的自动删除。
- 系统修复、注册表清理、内存加速等功能。
- 软件卸载、文件自动归档、云盘管理和网络共享管理。
- 为识别重复文件而默认读取全部文件内容。
- 在没有历史记录时推断过去的空间增长。
- 多平台同时发布、账号体系和跨设备同步。
- 通用 Shell 执行服务、绕过客户端沙箱的访问通道、Agent 托管和多 Agent 协作平台。
- 模型训练、Agent 长期记忆、知识图谱及事件自动触发任务；新讨论中的这些方向不自动进入产品范围。

上述首版排除项为范围建议，可在评审时调整。

### 4.2 核心能力清单

本表定义用户与 Agent 所需的业务能力，不规定工具名、命令格式或接口数量。CLI / MCP 按实际任务选取映射，允许覆盖重叠，复用同一套产品规则。

| 能力 | 输入意图 | 必须提供的结果 | 行为边界 |
| --- | --- | --- | --- |
| 发现扫描范围 | 查看可用磁盘及可访问范围 | 容量、支持状态、访问限制 | 只查询，不自动提权 |
| 扫描与任务控制 | 指定范围，开始、查询或取消扫描 | 任务标识、阶段、完整性、结果入口 | 读取目标元信息，可写入本地索引，不修改目标文件 |
| 查询和分析占用 | 对指定扫描结果进行搜索、筛选、聚合或钻取 | 对象、大小口径、统计时间、分页信息 | 查询已有结果，不隐式启动全盘扫描 |
| 查询候选与解释依据 | 判断哪些内容值得检查 | 规则命中、处理条件、影响、未知项 | 不将调用方推断当作已验证的可删除结论 |
| 创建与预览清理计划 | 从明确对象中选择处理范围与方式 | 计划标识与版本、具体清单、收益估计、恢复条件 | 可保存计划，不改动目标文件 |
| 执行计划 | 处理已获授权的计划版本 | 执行任务标识、逐项结果与错误 | 复核权限、范围和对象状态，记录实际副作用 |
| 验证与恢复查询 | 检查某次执行结果及可用恢复途径 | 对象状态、空间观测、未验证项、恢复说明 | 查询不再次清理；首版恢复仍使用系统回收站入口 |

执行能力需要包含完成该业务职责所必需的检查和记录。外部 Agent 负责选择目标、组合步骤和解释结果，不能代替 Orion 的执行前校验。

## 5. 核心用户流程

### 5.1 首次使用与扫描

1. 用户打开 Orion，看到可选择的磁盘和目录扫描入口。
2. 用户选择范围并开始扫描。
3. 页面显示扫描阶段、已发现文件数、已统计大小和运行时间。
4. 用户可以浏览已产生的结果，也可以取消扫描。
5. 扫描结束后，展示完成状态、未能扫描的范围和主要占用。

### 5.2 排查与清理

1. 用户从主要占用列表、分类或清理建议进入详情。
2. 查看路径、大小、用途说明、建议依据和清理影响。
3. 将需要处理的对象加入清理清单。
4. 生成清理计划，在预览页核对对象、处理方式、预计空间收益及恢复条件。
5. 确认当前计划版本后执行，查看逐项结果。
6. 检查对象处理状态和操作后磁盘可用空间，必要时进入恢复说明。

### 5.3 通过通用 Agent 使用 Orion（P1，核心功能完成后）

1. 用户按照接入文档，为已有的通用 Agent 配置 Orion CLI 或连接 MCP Server，并按客户端能力加载或参考 Skill 文档。
2. 用户向 Agent 提出任务，例如“查看 D 盘的主要占用，并列出值得检查的内容”。
3. Agent 查看已开放的能力及访问范围，先查询可用结果；需要新扫描时发起任务，取得标识并查询状态。
4. Agent 先查看概要，再按需筛选或钻取，向用户解释占用并生成清理计划；原始统计、规则依据和具体清单可核对。
5. 如开放清理执行工具，Agent 在用户对具体计划版本和处理方式的授权范围内执行。已有有效授权可继续使用，计划范围变化时重新核对授权。
6. Agent 查询执行结果，再调用验证能力检查对象处理和空间状态；结果未知时先查询，不重复发起清理。
7. 用户可在 GUI 中检查同一任务、计划及记录。开放执行工具与授权承接方式在接入阶段评审。

该流程对应“观察 → 计划 → 执行 → 验证”。用户只要求分析时，流程结束于观察或计划；目标空间收益无法达到时，应返回差额和限制，不自动扩大清理范围。

## 6. 详细功能需求

### 6.1 F-01 扫描任务（P0）

**用户故事：** 作为用户，我希望扫描指定范围时持续看到反馈，并能使用已经产生的结果。

功能要求：

- 支持扫描单个本地磁盘或用户选择的目录；首版建议一次运行一个扫描任务。
- 显示当前扫描范围、阶段、已发现文件数、已统计大小、耗时与异常数量。
- 结果随扫描逐步出现，明确标注“扫描中，结果尚不完整”。
- 总工作量未知时使用阶段和计数反馈，不显示没有依据的百分比或剩余时间。
- 支持取消；取消后保留本次已获得的结果，并标记为不完整。
- 扫描前说明需要的访问权限；权限不足时仍可完成可访问部分，并列出跳过范围。
- 文件消失、访问失败或磁盘断开时给出可理解的状态，避免长期停留在“扫描中”。
- 提供重新扫描入口；扫描时间可见，旧结果不得呈现为实时状态。
- 暂停、续扫与后台扫描不作为首版必需能力，另行评审。

### 6.2 F-02 空间总览（P0）

**用户故事：** 作为用户，我希望打开结果就能知道空间主要花在哪里，以及哪些内容值得检查。

功能要求：

- 磁盘扫描显示总容量、已用空间和可用空间；目录扫描显示所选范围内的统计信息。
- 展示按占用排序的主要目录，以及清理候选的汇总入口。
- 提供建议分类：应用与游戏、开发相关、个人文件、缓存与临时内容、系统相关、未分类；最终分类待评审。
- 无法识别的内容保留为“未分类”，不能强行归入可清理内容。
- 显示扫描状态、统计时间与未覆盖范围。
- 明确区分文件大小、实际占用和磁盘容量统计。无法取得的数值显示为未知，而非零。
- 当已统计文件与磁盘已用空间无法完全对应时，说明有未统计或未归属部分，不将差额归为可清理。

### 6.3 F-03 占用浏览与文件详情（P0）

**用户故事：** 作为用户，我希望通过清晰的列表逐层定位占用，并查看文件的基本信息。

功能要求：

- 建议以按大小排序的层级列表为主，支持面包屑返回和逐层进入目录。
- 支持按名称排序，以及按大小、类型、修改时间筛选当前扫描范围。
- 支持按名称或路径搜索已扫描结果，说明搜索范围是否完整。
- 详情至少包含名称、完整路径、类型、文件大小、可用的实际占用、修改时间和统计时间。
- 支持复制路径、在系统文件管理器中定位对象。
- 大量结果下按需显示，滚动与展开不能因一次性展示全部对象而失去响应。
- “较旧”“体积大”仅作为筛选条件，不自动代表无用或可安全删除。
- 图形可视化作为辅助方案，具体是否采用环形图、条形图等留待交互设计评审。

### 6.4 F-04 清理建议（P0）

**用户故事：** 作为用户，我希望知道某项为什么被建议清理，以及处理后可能发生什么。

功能要求：

- 首版建议从少量可验证的缓存、临时内容规则开始；具体应用及路径覆盖清单待确认。
- 每项建议包含对象、位置、占用、识别依据、处理条件、潜在影响、建议处理方式。
- 建议状态至少区分“符合已知清理条件”“需要人工判断”“受保护或不支持处理”。
- 同类候选可聚合展示，但确认前必须能查看实际处理范围。
- 已知缓存也要说明重新下载、重新生成或关闭相关应用等可能影响，不承诺无条件安全。
- 需要通过所属应用管理的内容，应提供明确说明；未支持对应处理方式时，不提供通用直接删除动作。
- 父目录与子项、多个规则命中同一对象时，需要合并或去重，避免空间收益重复累计。
- 支持忽略某条建议，以及将指定路径加入排除清单；用户可撤销忽略。
- 规则解释可独立查询，提供规则来源或版本、命中依据、检查时间及未验证条件；不需要模型生成解释。

### 6.5 F-05 清理清单、预览与执行（P0）

**用户故事：** 作为用户，我希望在执行前准确知道将处理哪些内容，并能控制处理范围。

功能要求：

- 清理候选默认不勾选，用户手动选择后加入清单；允许批量选择明确的一组对象。
- 预览展示完整路径或可展开的对象集合、对象数量、去重后的大小估计、处理方式和恢复条件。
- 预览形成可引用的清理计划，具有标识、版本、生成时间、来源扫描和状态；执行绑定具体计划版本，不能临时传入任意路径扩大范围。
- 计划明确区分可执行、被阻止和需进一步判断的项。候选内容或处理方式变更时更新版本，旧授权不能用于变更后的范围。
- 建立或查看计划不修改目标文件。计划可取消；对象状态、授权或处理条件变化时标记需要重新复核。
- 用户确认绑定计划范围与处理方式；有效授权在该范围内持续生效。授权获取与校验方式后续设计，调用方自行填写“已确认”不能替代真实授权。
- 首版建议以移入系统回收站为默认方式；不支持回收站的对象或位置应跳过并说明，不静默改为永久删除。
- 明确说明：移入同一磁盘的回收站通常不会立即增加该磁盘可用空间，最终释放需要清空回收站。
- 建议首版不内置永久删除及清空整个回收站，只提供系统回收站入口；是否增加需单独评审。
- 执行前重新核对对象是否仍存在、是否发生影响本次操作的变化，以及是否命中保护或排除条件。
- 扫描后新增、替换或变化的内容不得不经复核直接纳入已确认的删除范围；无法确认时跳过并提示。
- 清理时禁止与当前清单冲突的重复执行，显示处理进度；可取消后续操作，已完成的操作保留结果。
- 同一次执行请求重试或同一计划重复提交时，返回已有任务或结果；继续处理失败项需要重新核对范围，不再次处理已完成项。
- 单项失败不抹去其他项的结果，每项分别记录成功、失败或跳过及原因。
- 展示处理完成的对象大小与操作后磁盘可用空间；不能把前者直接宣称为实际释放空间。
- 执行后可独立查询验证结果，区分操作报告成功、对象状态已核实和尚未验证。磁盘空间变化需记录观测时间，其他程序同时写入造成的变化不能全部归因于本次清理。

### 6.6 F-06 操作记录与恢复（P0）

功能要求：

- 本地保留每次清理的时间、范围、处理方式、逐项状态和失败原因。
- 操作记录关联来源入口、计划版本和执行任务，用户可以从计划找到执行与验证结果；不记录外部 Agent 的内部推理。
- 对进入回收站的内容提供系统回收站入口及恢复说明；首版不承诺应用内一键恢复。
- 明确区分“可通过回收站尝试恢复”与“已恢复”，回收站被清空后不能承诺仍可恢复。
- 允许查看和清除操作记录，说明清除记录不会还原或再次删除原文件。
- 操作异常退出后，下次启动应能辨认未完成记录，提示复核；不能默认将未知状态记为成功。

### 6.7 F-07 通用 Agent 接入：CLI / MCP / Skill（P1）

**用户故事：** 作为已有通用 Agent 的用户，我希望它能直接使用 Orion 已实现的功能，完成空间排查和清理准备。

交付时序：核心阶段按第 4.2 节建立独立能力与共享状态；核心功能完成后提供对外入口和文档。具体接入组合、发布顺序及执行权限范围待评审。

#### 6.7.1 入口分工

| 交付物 | 产品职责 | 建议首批范围 |
| --- | --- | --- |
| CLI | 供人、脚本和具有终端能力的 Agent 调用，便于组合查询与复现问题 | 扫描、任务状态、占用查询、规则候选、计划预览、记录和验证查询 |
| MCP Server | 供支持 MCP 的客户端发现并调用有明确语义的业务能力 | 按任务需要映射扫描、查询、候选解释、计划、状态与验证能力 |
| Skill 文档 | 说明何时调用什么能力、怎样组合、如何判断结果与处理异常 | 同时说明适用的 CLI / MCP 用法、差异和兼容范围 |

CLI 与 MCP 是同一能力的不同入口，业务能力的粒度和约束不由入口形式决定。允许只使用一种入口完成受支持的流程；不强制用户或 Agent 在两个入口之间来回切换。MCP 接口不得仅转发任意 Shell 命令，CLI 也不得成为绕过计划检查的直接删除入口。

#### 6.7.2 能力发现与结构化结果

- 调用方可查看当前版本、可用能力、输入输出说明、访问范围及能力是否开放；不支持的能力有明确返回。
- 各入口对相同任务使用相同对象、计划与执行标识。工具执行不依赖 GUI 是否打开或当前选中哪一项。
- 输出包含数据、来源扫描、统计时间、完整性及必要的规则依据；数值单位和未知值的含义明确。
- 大结果集支持筛选、分页和聚合；说明返回范围、是否还有后续数据及结果所属版本，避免把单页内容误认成全部结果。
- CLI 提供适合人阅读的输出和稳定的结构化输出模式，建议使用 JSON；机器输出与进度、提示分离，调用方无需解析表格或颜色。
- 非交互调用不能无限等待终端输入；需要授权或用户动作时返回可查询状态和具体下一步。
- 错误同时提供稳定类别、可读原因、是否可重试、是否已产生副作用及恢复步骤；区分权限不足、范围不支持、结果过期、任务冲突和执行失败。

#### 6.7.3 任务、计划与授权

- 长时间操作返回任务标识，可查询状态、结果和取消；明确区分已接受、进行中、取消中、完成、部分完成、失败及结果未知。
- 请求超时或连接中断不代表任务未执行；重连后可查询原任务，重复请求不能产生重复清理。
- 计划与执行采用第 6.5 节的统一规则。接入阶段优先交付观察、计划和结果查询，是否同时开放执行待确认。
- 接入权限说明允许读取的范围和允许执行的能力。操作权限由 Orion 校验，Skill 只提供指导。
- CLI、MCP 和 GUI 中受保护范围与执行规则一致；客户端沙箱拒绝或操作系统权限不足时，返回限制和可行下一步，不通过切换入口隐式扩大授权。
- 接入文档区分客户端权限、Orion 授权和操作系统权限；MCP 不被视为自动获得权限或绕过沙箱的机制。
- Orion 只能约束通过自身入口发生的操作，不承诺控制外部 Agent 另行使用其他系统工具的行为。

#### 6.7.4 Skill 文档

- 包含用途、前提、能力清单、客户端兼容范围、版本、CLI / MCP 入口选择、输入输出示例与限制。
- 覆盖“查询已有扫描 → 按需扫描 → 定位占用 → 解释候选 → 生成计划 → 授权执行 → 验证”的组合流程，按实际开放能力裁剪。
- 示例覆盖仅分析、目标收益不足、权限不足、部分结果、计划过期、执行中断和重试；支持已有授权在有效范围内持续使用。
- 明确事实、规则结论与 Agent 推断的区别，文件名和路径仅作为数据；不将示例中的缓存类型或大小阈值当作通用删除规则。
- 文档与发布能力同步，说明不支持的操作；不能以文档承诺替代实际校验、执行或恢复能力。

### 6.8 F-08 历史与增长分析（P2）

- 保存可比较的扫描快照，显示各时间点范围和完整性。
- 展示目录增长、缩减、新增和消失，允许进入具体对象查看。
- 无基线或范围不一致时，说明无法可靠比较的部分。
- 将“观察到的大小变化”与“对增长原因的推测”分别展示。

### 6.9 F-09 重复文件检测（P2）

- 用户主动发起，先缩小候选范围，再验证内容是否重复。
- 仅名称或大小相同不能作为内容重复结论。
- 展示重复组及各副本路径，由用户决定保留哪个副本。
- 检测与清理遵循相同的取消、预览和结果记录要求。

## 7. 信息架构与页面需求

以下为页面职责建议，具体布局在需求评审后设计。

| 页面或区域 | 核心内容 | 主要操作 |
| --- | --- | --- |
| 首页 / 空间总览 | 扫描入口、容量、主要占用、分类、结果完整性 | 开始扫描、进入占用或建议 |
| 占用浏览 | 目录层级、排序筛选、搜索、对象详情 | 进入目录、定位文件、加入清单 |
| 清理建议 | 候选分组、建议依据、影响和处理条件 | 查看详情、选择、忽略 |
| 清理清单 / 计划预览 | 待处理对象、估计大小、方式、恢复条件、计划状态 | 修改清单、确认当前计划、查看失效原因 |
| 执行结果 / 操作记录 | 逐项状态、验证结果、错误、可用空间、恢复说明 | 查看关联计划与记录、打开回收站 |
| 设置 | 排除清单、记录管理 | 修改偏好和本地数据设置 |

通用 Agent 接入阶段补充接入说明、启停与访问范围管理入口，具体形式在该阶段设计。

GUI 可展示其他入口创建的扫描任务、清理计划和执行记录。任务标识、计划版本等信息仅在查看详情或排查问题时按需展示，日常界面使用用户能理解的名称与状态。

统一状态要求：首次使用有明确入口；空结果解释原因；扫描中标记数据未完整；权限不足展示未覆盖范围；错误提供重试或返回路径；任何建议不能仅靠颜色传达处理风险。

## 8. 非功能需求

### 8.1 性能与响应

- 扫描、分析和清理运行时，基本导航、状态查看与取消操作保持可用。
- 大量小文件、深层目录及大结果列表为必测场景；建议包含百万级文件压力数据集。
- 不因提高扫描速度而默认无上限占用 CPU、内存或磁盘资源。
- 取消按钮立即有反馈；任务结束存在延迟时持续显示取消中状态，并说明仍在等待的操作。
- 性能报告需同时记录完成耗时、资源使用、界面响应和结果完整性。

### 8.2 统计正确性与可靠性

- 需要处理权限拒绝、长路径、特殊字符、文件变化、链接、硬链接、稀疏或压缩文件等情况。
- 链接和共享数据不能导致无限扫描或重复宣称可释放空间；统计能力不足时明确标注估计或未知。
- 明确扫描是否跨越所选范围；默认不通过链接扩展到未经用户选择的位置。
- 不自动读取仅在线文件的内容以触发下载；无法支持的对象需说明。
- 扫描中断、清理失败和应用异常退出不能导致结果状态被误报为完成。

### 8.3 数据与隐私

- 扫描结果和操作记录默认保留在本机。
- 用户可以清除应用保存的扫描数据和操作记录，且不会因此改动原文件。
- 启用外部 Agent 接入时，说明可访问的数据类别与路径范围，并支持关闭接入。
- 工具仅返回任务所需且在允许范围内的数据；文件正文读取不纳入本草案范围。
- 接入文档说明：工具返回的数据会交给外部 Agent，其后续处理及是否使用云端模型由用户所选客户端决定；不能将外部 Agent 的数据处理承诺为 Orion 的本地处理保证。
- 不默认上传遥测、完整路径、文件内容或诊断日志；成功指标可通过本地验收测试验证。

### 8.4 易用性与兼容性

- 建议首版以简体中文为主要界面语言。
- 完整路径可复制；长文本有可查看完整内容的方式。
- 主要流程支持键盘操作，焦点与选中状态清楚，文字与控件保持可读。
- Windows 版本、磁盘格式及可移动磁盘支持范围待确认；不支持时应给出明确说明。

### 8.5 能力契约与可观察性

- 核心阶段定义能力输入、输出、前置条件、副作用和状态；外部接口发布时提供可识别的版本。
- 对外命令、工具参数、错误类别或字段含义发生不兼容变化时，给出版本差异及迁移说明，不静默改变旧调用的含义。
- 对同一扫描结果的查询应提供一致的数据视图或说明版本变化；进行中的统计不得伪装为固定快照。
- 扫描、计划、执行和验证信息可关联。记录必要的入口、操作范围、时间与结果，支持定位失败；不默认收集对话或模型推理。
- 接口、CLI 帮助和 Skill 文档按同一发布版本检查，确保示例对应实际支持的能力。

## 9. 数据需求

本节定义产品需要表达的信息，不约束存储实现。

| 数据对象 | 必要信息 |
| --- | --- |
| 扫描任务 | 任务标识、范围、起止时间、状态、结果版本、统计口径、覆盖范围、异常摘要 |
| 文件或目录结果 | 可引用的对象标识、路径、类型、大小信息、时间、所属扫描、结果新鲜度 |

| 操作授权 | 对应计划版本、允许范围与方式、授权来源、有效状态；具体授权机制另行设计 |
| 清理任务 | 执行任务标识、关联计划、授权范围、来源入口、执行时间、逐项结果、重复请求关联信息 |
| 验证结果 | 关联执行、对象状态、验证时间、空间观测及口径、未验证项、恢复信息 |

| 历史快照（P2） | 统计时间、范围、完整性、可比较的占用数据 |

扫描数据及日志的保留时长、默认容量上限和自动过期规则待确认。

## 10. 验收标准

以下为首版验收主清单；最终范围按需求评审结果调整。

| 编号 | 验收场景 | 通过条件 |
| --- | --- | --- |
| A-01 | 首次启动、独立运行 | 无需接入外部 Agent，可选择范围并完成扫描 |
| A-02 | 扫描大量文件时浏览结果 | 有持续状态反馈，能切页、浏览已有数据和发起取消 |
| A-03 | 部分目录无权访问 | 其余范围可完成，结果明确显示不完整和跳过原因 |
| A-04 | 用户中途取消扫描 | 保留已有结果并标记不完整，可重新发起扫描 |
| A-05 | 查找主要占用 | 能按大小排序、逐层进入并定位到具体文件或目录 |
| A-06 | 查看清理建议 | 能查到依据、影响和处理条件，未知对象不会被强行标为可清理 |
| A-07 | 同时选择父目录与子项 | 预览不会重复累计或重复处理相同对象 |
| A-08 | 确认后对象发生变化 | 不直接处理未经复核的变化范围，提示跳过或重新确认 |
| A-09 | 对象无法进入回收站 | 明确跳过和说明原因，不改为永久删除 |
| A-10 | 部分清理成功、部分失败 | 逐项结果准确，成功与失败数量不混淆 |
| A-11 | 文件进入同盘回收站 | 不将移入回收站的大小宣称为已释放空间，提供后续说明 |
| A-12 | 查看清理历史 | 能查到处理方式、状态及恢复入口，清除记录不改动原文件 |
| A-13 | 链接、特殊文件或统计差额 | 不无限扫描、不误报收益，无法确定部分有说明 |
| A-19 | 不经 GUI 操作核心能力 | 能完成扫描、查询、建计划、授权执行与验证；结果不依赖页面状态 |
| A-20 | 预览或修改计划 | 预览不修改目标文件；变更产生新版本，旧授权不能用于变更范围 |
| A-21 | 重复提交、超时后重试 | 同一次执行返回已有任务或结果，不再次处理已完成对象 |
| A-22 | 核对实际清理效果 | 对象状态与空间观测分开报告，未验证项明确标注，不把其他程序造成的空间变化全部归因于 Orion |

通用 Agent 接入阶段补充验收：

| 编号 | 验收场景 | 通过条件 |
| --- | --- | --- |
| A-14 | 按文档接入通用 Agent | 通过已发布的 CLI 或 MCP 可完成扫描、查询、候选解释、计划预览及结果查询，无需为 Orion 配置模型 |
| A-15 | 跨入口继续同一任务 | GUI、CLI、MCP 对同一任务及版本使用一致的统计和规则，能定位同一计划、执行与验证记录 |
| A-16 | 大结果或长时间任务 | Agent 可分批查询、查看进度和取消，返回结果说明完整性及范围 |
| A-17 | 超范围访问或未经授权的清理 | Orion 拒绝调用并返回原因，Skill 文档不能代替实际权限控制 |
| A-18 | 接入断开或关闭 | 桌面功能继续可用，已有任务状态可核对，不因重连重复执行清理 |
| A-23 | 机器读取 CLI 输出 | 输出可解析、单位明确，日志不污染结果；无需模拟终端交互即可得知所需用户动作 |
| A-24 | 查询能力或遇到权限限制 | 能获取已开放能力及版本；权限错误有原因和下一步，不自动通过另一入口扩大权限 |
| A-25 | 依据 Skill 处理异常 | 示例可复现，只分析、过期计划、部分失败和重试都有适用流程，不依赖未实现能力 |

各入口验收仅针对该阶段实际发布的能力。A-19 验证核心能力独立性，不要求首版同时发布 CLI 与 MCP；A-14 至 A-18、A-23 至 A-25 在对应入口交付时执行。

## 11. 版本规划

| 阶段 | 目标 | 交付内容 | 退出条件 |
| --- | --- | --- | --- |
| 需求评审 | 明确目标、能力与边界 | 本 PRD、核心能力清单和用户流程的修订与确认 | 首版关键问题及能力输入输出、状态和约束有结论 |
| 交互验证 | 验证核心流程是否易懂 | 总览、浏览、清理预览及结果页原型 | 用户能够完成排查和清理决策任务 |
| MVP | 完成核心使用闭环 | 经确认的 P0 功能、可独立调用的能力、共享计划与任务状态 | 桌面流程及核心能力验收项通过 |
| 通用 Agent 接入 | 将已实现的能力开放给外部 Agent | 经确认的 CLI / MCP 入口与 Skill 文档 | 端到端任务及异常流程验收通过，各入口行为一致 |
| 后续迭代 | 增加变化分析等能力 | 按反馈推进历史、重复检测等 | 每项能力独立明确需求和验收标准 |

技术选型在需求范围确认后进行，开发排期在技术方案和任务拆分完成后制定。

## 12. 风险与依赖

| 风险或依赖 | 产品影响 | 应对要求 |
| --- | --- | --- |
| 设备与目录结构差异 | 扫描耗时不可统一预测 | 使用典型数据集验收，并保持可见反馈 |
| 访问权限与磁盘特性 | 无法覆盖全部占用 | 展示覆盖范围，保留部分可用结果 |
| 清理规则错误或过时 | 建议可能不适用 | 控制首版覆盖面，展示依据和条件，允许忽略 |
| 外部 Agent 误读结果或调用不当 | 用户可能得到不准确解释，或发起不适用操作 | 返回统计依据及完整性，明确工具语义，由 Orion 校验操作范围 |
| 接入客户端能力差异 | CLI、MCP 或 Skill 文档无法按预期使用 | 选定目标客户端验证，记录兼容范围与接入步骤 |
| 客户端沙箱与本机权限不一致 | Agent 能连接但无法完成某些操作 | 明确各层权限及拒绝原因，不能承诺换协议即可解决 |
| 各入口独立维护业务流程 | 统计、授权和执行结果出现差异 | 复用核心能力与状态，验证相同任务在各入口的行为 |
| 接口或文档变化 | 既有脚本及 Agent 工作流失效 | 明确版本和兼容范围，发布时验证示例 |
| 扫描与执行之间文件变化 | 清单与实际内容不一致 | 执行前复核，变化时跳过或重新确认 |
| 回收站与立即释放空间的差异 | 用户误以为空间已经释放 | 分开显示处理大小和实际可用空间 |
| 功能范围扩张 | 首版难以收敛 | 优先完成确认后的核心流程，再增加扩展功能 |

## 13. 待确认问题

建议优先讨论 Q-01 至 Q-06；Q-13 至 Q-15 用于进一步明确新增的能力和接入需求。

| 编号 | 待确认问题 | 草案建议 |
| --- | --- | --- |
| Q-01 | 首版只支持 Windows 吗？需要哪些版本、磁盘类型？ | 先聚焦 Windows 本地磁盘，明确支持矩阵 |
| Q-02 | 首要用户是自己和开发者，还是一般个人用户？ | 先围绕个人使用验证，确定重点占用类别 |
| Q-03 | 核心功能完成后，CLI + Skill 与 MCP 如何安排发布顺序，优先适配哪些通用 Agent？ | 建议评估先交付 CLI + Skill，再按客户端需要提供 MCP；不预设两套接口必须同时发布 |
| Q-04 | 首版是否需要完整清理能力，还是先做只读分析？ | 建议包含可控清理流程，支持实际完成任务 |
| Q-05 | 是否接受先移入回收站，再由用户在系统中释放空间？ | 首版采用此方式；如需立即释放，另行定义不可恢复操作 |
| Q-06 | 首版清理规则覆盖哪些应用和内容？ | 先选最常见且能验证处理影响的一小组 |
| Q-07 | 主要浏览方式是否接受层级列表？是否需要图形总览？ | 列表为主，图形辅助，通过原型验证 |
| Q-08 | 暂停续扫、退出后恢复、后台监控是否首版必需？ | 首版仅要求取消与重新扫描 |
| Q-09 | 历史变化和重复文件检测是否需要提前？ | 暂列 P2 |
| Q-10 | 哪台设备、什么规模作为性能验收基准？ | 确定真实设备及典型小文件、大文件混合数据集 |
| Q-11 | 扫描结果和操作记录默认保存多久？ | 先保留最近结果和必要操作记录，提供手动清除 |
| Q-12 | 产品名、界面语言和发布对象是否确定？ | 暂用 Orion、简体中文，先个人试用 |
| Q-13 | Agent 接入首批是否开放清理执行？如何承接用户授权？ | 先提供观察、计划、记录与验证查询；开放执行时绑定具体计划版本，有效授权可持续使用 |
| Q-14 | 第 4.2 节的能力粒度是否合适？是否需要额外的业务能力？ | 用实际任务验证组合是否足够，避免只提供底层文件操作或一个包办所有工作的入口 |
| Q-15 | 对于客户端沙箱限制和权限不足，期望支持哪些部署及使用情形？ | 先围绕用户本机和明确授权范围验证；具体权限承接方式在技术方案阶段决定 |
