# Orion · Product Spec

这是我们共同开发 Orion 的轻量产品说明：背景、角色、功能行为和重要取舍。每项功能用一个用户故事说明用途，再写清基本行为与边界。本文是当前草案，不代表功能已经实现；新的讨论和试用反馈直接更新到这里。

## 背景

我经常用 SpaceSniffer 查找磁盘占用，但不喜欢它的界面；使用 TreeSize 等工具时也遇到过卡死。我想做一个自己愿意日常使用的工具：看清空间花在哪里，理解哪些内容值得整理，然后决定如何处理。

项目暂称 **Orion**。当前先围绕个人电脑、本地磁盘使用场景展开，Windows 优先作为工作假设。

## Actors

| 角色 | 职责 |
| --- | --- |
| 用户 | 提出需求、浏览结果，决定保留什么以及授权处理什么 |
| 通用 Agent | 在用户已有的 Agent 环境中理解目标、组合工具、解释结果 |
| Orion | 提供扫描、查询、规则分析、清理计划、执行与验证能力，并落实操作约束 |

我们用聊天 Agent 协作开发 Orion；产品中的“通用 Agent”指未来调用 Orion 的外部客户端。Orion 本身不内置聊天助手或模型服务。

## 功能 Spec

产品整体围绕“扫描 → 查看占用 → 判断候选 → 预览处理 → 查看结果”展开。以下功能描述包含后续方向，不表示都在本轮实现；通用 Agent 接入在核心功能可用后补上。

**当前迭代：只读扫描与占用浏览。** 具体范围、任务顺序和进展统一维护在 [MVP Task Plan](MVP_TASK_PLAN.md)。架构与选型理由见 [Tech Stack](TECH_STACK.md)。

### 扫描磁盘或目录

**用户故事：** 我想扫描选定的磁盘或目录；文件很多时，也能知道进展、查看已有结果并取消任务。

- 选择一个本地磁盘或目录开始扫描，显示当前范围、阶段、已发现文件数和已统计大小。
- 结果逐步可见，浏览和取消保持可用。取消后保留已获得的部分结果，可重新扫描。
- 扫描结果带时间与完整性说明。权限不足、文件消失等情况说明跳过范围和原因，其余可访问部分继续处理。
- 总工作量未知时显示阶段和计数；不编造百分比或剩余时间。
- 扫描任务由独立后端管理，关闭界面或断开客户端不自动取消；后端仍运行时，重新连接可继续查看同一任务。后端重启后的恢复能力另行决定。

### 查看和定位占用

**用户故事：** 磁盘快满时，我想快速找到主要占用，并逐层查看具体目录和文件。

- 展示扫描范围的占用汇总和最大的目录、文件；整盘扫描同时展示磁盘容量与可用空间。
- 支持按大小排序、逐层进入与返回、按名称或路径搜索，以及按类型和修改时间筛选。
- 对象详情显示完整路径、大小、修改时间；可复制路径或在系统文件管理器中定位。
- 区分文件大小、实际占用和未统计部分，无法取得的数据标为未知。查询基于当前扫描结果，不隐式重新扫描。
- 当前从层级列表起步，demo / MVP 使用 Tauri + React 探索列表、图形和混合布局，具体呈现通过试用调整。

### 理解内容与清理候选

**用户故事：** 遇到陌生的大目录时，我想知道已有的用途线索，以及清理它可能带来的影响。

- 用已知规则提供用途分类和清理候选，展示命中依据、处理条件、可能影响与建议方式。
- 未知内容保留为未知。大文件、旧文件和缓存名称都不能单独证明内容可删。
- 可以进入候选项查看具体对象，也可以忽略建议或排除某个路径。
- 从少量能验证的规则开始；需要应用自身管理的内容，未支持对应处理方式时只作说明。

### 清理计划与结果

**用户故事：** 我想选好要处理的内容，核对清单后执行，并知道哪些成功、哪些失败、能否恢复。

- 用户选择对象后形成可查看的清理计划，展示具体清单、处理方式、去重后的大小估计及恢复条件。生成计划不改动目标文件。
- 执行仅覆盖已授权的计划内容；已有有效授权持续生效，范围或对象变化时重新核对。
- 显示逐项成功、失败或跳过的结果及原因；可停止后续操作，已完成部分保留记录。中断后先查原任务，避免重试造成重复处理。
- 执行后可查看对象状态、磁盘可用空间及恢复说明，明确尚未验证的部分。
- 处理方式暂未定案。若使用回收站，需说明移入同盘回收站通常不会立即释放空间；不支持某种方式时不静默改成永久删除。

### 通用 Agent 接入

**用户故事：** 我想在常用 Agent 中提出磁盘管理任务，让它使用 Orion，并能在界面中核对同一份结果。

- 对外提供已实现的扫描、查询、候选解释、计划与结果查询能力；是否首批开放清理执行另行决定。
- CLI 方便人、脚本和 Agent 调用；MCP 提供工具接入；Skill 说明用法和组合流程。按实际需要交付，不必同时做齐。
- 返回结构化结果，支持先看概要再查明细。长任务有标识、可查状态和取消；错误说明原因与下一步。
- 各入口共用任务、计划、结果和执行约束，不依赖 GUI 当前选中项。Skill 不代替权限检查，切换入口不能隐式扩大授权。
- Orion 提供事实与规则依据，外部 Agent 负责推断和编排；接入时说明会向客户端提供哪些数据。

## 共同原则

- **独立后端、统一 API：** 扫描与后续业务能力由独立 Server 管理，CLI / MCP / UI 共用后端 API 和任务状态，各入口保持轻量。
- **响应与准确性优先：** 扫描时仍能操作，事实、估计与未知项分清；性能用真实目录验证。
- **处理可控、结果可查：** 只处理授权范围，如实表达副作用、实际空间收益和恢复条件。
- **本地为默认：** 扫描数据和记录保留在本机，外部 Agent 的数据处理另有边界。
- **边做边改：** 每次围绕一个用户故事交付可运行的结果，做必要验证后试用；只把影响产品行为的重要决定补回本文。

## 暂缓与待定

历史增长、重复文件检测和后台监控先留作后续方向。当前不展开内置 AI、系统优化或通用 Agent 平台。

做到相关部分时再决定：

- 清理先支持哪些内容；回收站、立即释放空间和恢复能力如何取舍。
- CLI / MCP 的交付顺序，以及首批是否开放执行能力。
- 具体界面和支持的磁盘范围，通过接下来的实现任务确定；技术方案建议见 [技术选型](TECH_STACK.md)。

旧版 PRD 仅保留讨论历史，旧草案里的提议不自动成为必做需求。具体接口、数据结构和测试细节跟着当前实现任务确定。
